fashion.txt: how this project is built, and how to add to it

Read this before you change anything. It is written for the next person or agent who gets a prompt
about this project. It is the project's memory: when you learn something the hard way, add it here.

======================================================================
START HERE
======================================================================

What this is: w11-cli-console, a Windows 11 settings console in Python. "py app.py" opens an
interactive console; "py app.py <setting> <words>" runs one command and exits. Each setting is one
.py file (a "page") in the project folder, and app.py finds it by itself.

The goal: someone who has never seen this tool should be able to type "settings", find the setting
they want, read its intro, and do the job without leaving the terminal. Typing a setting name alone
(vm, bn, su, prc, net) shows that intro. Plain words, one action per line, no jargon the user has to
look up. An AI agent troubleshooting someone's PC should be able to run the same commands and read
the results as data (--json).

When you get a prompt:
1. Read this file and README.md, then the existing page closest to the request (see "Which file to copy").
2. Find out how Windows does it, read-only, in scratch scripts outside the project: a winreg read, a
   WMI query, a WinRT call, a "netsh ... show". Check it works on this PC, and whether it needs
   administrator rights, before you build on it.
3. Write the page, or extend one. Code two pages need goes in _core.py or _net.py, not in both pages.
4. Test it the safe way (see TESTING).
5. Update README.md and this file (see FINISHING).
6. In your reply, say what you verified on this PC and what you could not. Usually that is anything
   that needs administrator rights, because the terminal you get is normally not elevated.

Which file to copy:
- a list with ids, then act on one id .......... volume.py
- on/off switches for things in a list ........ startup.py
- registry policies, admin check, read-back ... location.py
- a page built on _net.py ...................... ethernet.py (the smallest)
- a Windows Runtime (WinRT) API ................ hotspot.py
- netsh, and many settings under headings ...... wifi.py
- an interactive page with its own prompt ...... regedit.py
- a list built from Windows' device API (ctypes, cfgmgr32) .. device.py
- changes made through a Windows tool and read back (pnputil for devices, the NetSecurity cmdlets for the firewall),
  each checking admin rights before the question .. device.py (CHANGES), firewall.py
- reading the Windows event logs (one PowerShell Get-WinEvent call per query) .. events.py
- a live view that redraws in place, sorted tables, per-program groups, sampled history, and
  actions that ask first (ending a process, a firewall block) .. netmon.py (psutil for connections
  and adapter counters; _net for adapters; process.py's protected-name rule)
- read-only reports on hardware or live load (no changes, shared readings) .. hardware.py, system.py
- a status page with a verdict, a "why" command that names the fix, and switches that refuse politely when a policy
  or Tamper Protection owns them (PowerShell cmdlets, read back) .. defender.py, update.py
- a registry tree of per-app switches with policy overrides and "in use now" .. privacy.py (after location.py)
- ctypes against a Windows API with a change that undoes itself unless confirmed in time .. display.py
- WinRT devices, discovery and pairing with prompts answered by hand .. bluetooth.py (after hotspot.py)
- COM interfaces declared by hand with comtypes, including one undocumented call with a read-back .. sound.py
- editing values with a backup before every change, and undo .. environment.py
- measuring with a Windows trace session that is always stopped (logman + Get-WinEvent) .. netmon.py (net bytes)
- files kept in %LOCALAPPDATA%\w11-cli-console (snapshots, backups, caches) .. _win.data_dir; device.py (backup), environment.py
- read-only views of a Windows service: sc queryex, registry for config .. services.py (the read-only section)

LESSONS FROM hardware.py AND system.py
- Readings that Windows gives ordinary users blank (SMART, BitLocker, TPM, thermal, failure prediction)
  must say "needs administrator rights", not show "-". _probe.reason() maps the error text to that.
- Put every PowerShell reading in one call, with each reading inside its own try (Get-Part in _probe.PRELUDE).
  One refused reading then becomes an entry in "unavailable" rather than stopping the rest.
- The processor API (GetLogicalProcessorInformation) has 32-byte entries: the detail union starts at
  offset 16, not 12. The padding in _probe._Info is what keeps it right. Check it against a known value
  (this PC: 32 KB L1 per core, 512 KB L2 per core, hyper-threading on all 16 cores).
- GPU video memory: Win32_VideoController.AdapterRAM is 32-bit and wrong above 4 GB. Read
  HardwareInformation.qwMemorySize under the display class key in the registry instead.
- Performance counters count each logical processor as 100%. Divide by the count for a share of the whole PC
  (sys processes does this and leaves the idle process out).
- "% Processor Performance" and "Processor Frequency" can disagree on some AMD chips: say which one a
  number came from, and label estimates as estimates.
- Get-Tpm returns blank fields without administrator rights; a blank is not a missing TPM.

======================================================================
ENVIRONMENT (this PC, as last seen)
======================================================================

- Windows 11 Pro. Python 3.14, run as "py". Packages: pycaw, psutil, comtypes, and the winrt-*
  packages (pywinrt 3.2, which has wheels for 3.14).
- The terminal is usually NOT elevated. HKLM writes, netsh interface, netcfg, starting services and
  connection sharing all fail with "needs administrator". Build the admin check in, test that it
  refuses cleanly, and report those paths as unverified.
- There are two shells, Git Bash and PowerShell. Git Bash rewrites some slash arguments into file
  paths: "ipconfig /all" and "reg query ... /v" break there, so run those in PowerShell. A Python
  script in the scratchpad is easier than a one-liner when the code has backslashes or quotes.
- Set PYTHONIOENCODING=utf-8 when you pipe app.py's output. The banner has box characters that
  crash a cp1252 console.
- Captured output shows colour codes as raw text, such as [34m. That is expected.
- Git: remote "origin" is github.com/h-kakar11/w11-cli-console, branch main. Commit and push only
  when asked. If GitHub "shows no updates", check "git log origin/main..main" for commits that were
  never pushed (that was the cause once). The __pycache__/*.pyc files are tracked by mistake and
  change on every run. Before you finish, restore them with "git checkout -- __pycache__/" and
  delete any new untracked .pyc. There is no .gitignore yet.

======================================================================
THE PAGE CONTRACT
======================================================================

1. Header block. Constants that app.py and settings.py read:

NAME = "volume"                   # the command word
ALIASES = ["vm", "vol"]           # short forms; must not clash with any other page's name or alias
SUMMARY = "Alter system and per-app volume"     # under about 60 characters: it is all the settings list shows
USAGE = "vm ls | vm <id> | vm <id> <0-100>"

2. The intro. Shown in blue when the user types the setting alone, or with help, ?, -h or /?:

HELP = [
    ("vm ls", "list every audio source with its id (0 is the system)"),
    ("vm <id>", "show the volume of one source"),
    ("vm <id> <0-100>", "set one source to that percent"),
]
TIP = "Example: vm 3 50 sets source 3 to 50%. Ids follow the list, so run 'vm ls' first."

HELP is one row per thing the user can do: the exact words to type, then a short description. Put
the most common action first, since settings.py shows the first row as "START WITH". Keep it to about
six rows. TIP is optional: one line with an example, or the one thing that most often goes wrong.
app.py draws the block, so pages never print their own intro. A page without HELP shows its USAGE
line instead.

A page with many settings (wifi) groups its rows under short headings rather than cutting them. A row
with an empty syntax, such as ("", "known networks"), is a heading. The five or six everyday actions
still come first, before any heading, so the intro reads like a small page until you look further.

RUN_ALONE = True means typing the name alone runs the page instead of showing the intro. settings,
location, regedit, firewall, netmon, defender, privacy, display, bluetooth, sound and update set it, because the
name alone is a useful command (a status) and changes nothing; "<name> help" still shows the intro, and the status
ends with a line saying so. Never set it on a page where the name alone would change something.
Pages may also set KEYWORDS = [...] (words people use that the name and intro do not contain): "settings search"
reads them.

3. One entry point. run(args) gets the words after the name and returns an exit code:

0 success
1 system or device error, including "needs administrator rights"
2 bad usage

app.py handles a bare name and help words before run() is called. run() still handles them too, so
the file also works as "py page.py ...". Each page has its own error class with a code. run() catches
it, prints "error: ..." to stderr and returns the code. Pages built on _net.py also catch
_net.NetError.

4. Flags for agents. run() starts with:

    args, options = _core.split_flags(args)    # options["json"], options["yes"]

--json makes a reading command print plain data with the same keys every time (no colour, no prose).
--yes answers a confirmation in advance. An agent passes it only after the person has agreed to that
change. Every page takes both, except regedit, which is interactive. location also has --override-management.
"settings --json" lists every setting, its short forms and every command with what it does, as data: that is where an
agent should start. Pages that print their status when typed alone set RUN_ALONE, and "<name> help" shows their intro.

======================================================================
RULES
======================================================================

5. Subcommands use the same words everywhere.

Listing: ls or list
Removing: rm, remove, delete, uninstall, del
Toggling: on/enable, off/disable
Show or set one item: <id> shows it, <id> <value> sets it
A setting name alone after the page shows what it is now and how to change it (wifi dns, eth auth).
Accept the long and short forms in every page. The README says the same thing.

6. Ids come from one function. Build the list in one function, sort it alphabetically, number it
from 1, and use that same function for the listing and the action, so they always agree. Tell the
user that ids can shift when the list changes. Where you can, also accept a stable name (wifi
features ipv6, not only wifi features 6), because names do not shift and agents can rely on them.

7. Output.

Listings use one line per item, with an id and a name, and are coloured per row. Call os.system("")
once to turn colour on in the Windows console.
Long details (wifi info, eth info, hs status) are sections, each in its own colour, through
_net.render. Use the same palette as process.py: cyan, green, yellow, magenta, blue. In lists, green
means on or connected, grey means off, and red means not installed or a protected system item.
For long lists, print down each column and then start the next one, using the terminal width from
shutil.get_terminal_size().
Print results on one line, such as Discord: 90%.
Show what the person needs next. If a value explains a common problem, say so next to it, as eth
info does with a 169.254 address: "self-assigned: no DHCP server answered".

8. Check before you announce. If a change needs administrator rights, check that first (need_admin
or is_admin), so the page never says "turning X off..." and then fails. Check bad words and bad
values before the admin check too, so bad usage gets exit code 2 and a usage line.

9. Say what to expect, then do it, then read it back. Print one line before a change ("expect a short
drop while it asks the router"). After it, read the setting back from Windows and report what it is
now, not what you meant to write (as JSON with --json). If the change applies later (next sign-in,
next hotspot start), say so.

10. Confirmations. Ask before anything that can't be undone, say what will happen, and treat
anything other than y or yes as no. Also ask before a change that can be undone but can cut the
person off: a manual IP address, turning IPv4 off, sharing a connection (which replaces the other
adapter's IP). Put the undo command in the question. A wrong value can leave the person, or the
agent, without the connection they need to fix it. Always use _core.confirm(question, options["yes"]).

11. Prefer reversible changes. Change a switch or a value rather than deleting something. startup
turns apps off by changing Windows' approval entry, so nothing is lost.

12. Python first, then Windows' own tools, then PowerShell.

Use winreg, ctypes, comtypes (COM and WMI) or a package such as pycaw or winrt where possible.
Use netsh, sc or netcfg when they are the documented way (wifi, 802.1X, network features).
Use PowerShell only when there is no other route, and only for that part.
Add any new package to requirements.txt and install it.

13. Never guess at hidden settings. When Windows has no API or documented setting for something,
do not write registry bytes you have not seen documented. Open the exact Settings page with
os.startfile("ms-settings:...") and say what to choose there. The hotspot's "Share over" works
this way. Never get around Windows' permissions or an organisation's policy without the person's
explicit say-so (see location's --override-management).

14. Make it easy for a person, not just a script. Before you finish a page, ask: if someone types
"settings" and finds this line, would the next step be obvious? The first HELP row should be the
thing they most likely want.

15. Interactive pages (like regedit) read their own lines, and must not rely on the console's
shlex.split. shlex treats a backslash as an escape, so HKLM\SOFTWARE arrives as HKLMSOFTWARE. Such a
page splits its own lines, keeping backslashes and honouring quotes, as regedit.py's _tokens does.

======================================================================
TESTING (without side effects)
======================================================================

- Read everything first: run each reading command, with and without --json, and compare with what
  Windows shows (ipconfig in PowerShell, Settings, netsh).
- Write the value it already has: name to the same name, a switch to the state it is in. Some
  Windows writes may leave a trace even then (re-writing a Wi-Fi profile's cost can change its
  "Cost Source" from Default to User), so prefer switches where re-writing is truly the same.
- Answer "n" to confirmations (echo n | py app.py ...) and check that nothing changed afterwards.
- Check bad ids, bad words and bad values, and look at the exit codes (2 for bad usage).
- Without administrator rights, check that every admin-only change refuses before announcing anything.
- Only make a real change when you can put it back straight away (hotspot on, then off).
- Test the pure parts directly: parsers, XML edits, table building. Import the page or _net.py from
  a scratch script.
- Read the intro: type the setting name alone and read it as a new user would. Check that it
  appears correctly in "settings".
- Run every page's intro once after changing _core.py, since every page uses it.
- Compile everything: for f in *.py; do py -m py_compile "$f"; done
- Sessions that run in a Linux container cannot run Windows at all. Pages written there (netmon, firewall, device
  changes, and the pages after them) were tested with the Windows side faked: a winreg stub backed by a dictionary, a fake
  ctypes.windll, a fake subprocess that answers PowerShell, pnputil, logman and the rest by matching the command text,
  stub pycaw, comtypes and winrt, and builtins.input replaced to give the answers. That proves the page's logic, its
  output, its --json keys, its exit codes, and that it asks before it changes anything. It does not prove what Windows
  returns, so every such page has an OPEN ISSUES entry that lists what to look at on a real PC. Those test scripts live
  outside the repo (there is no tests folder). If you write a page without Windows, build the same kind of fakes, run
  python with PYTHONDONTWRITEBYTECODE=1 so no .pyc lands in the project, and say what you could not check.

======================================================================
WINDOWS LESSONS (learned the hard way; add to this)
======================================================================

Wi-Fi and netsh
- netsh output is in the OEM code page: run it with encoding="oem".
- "netsh wlan show networks" needs Location on for apps, or Windows hides the names. "show
  interfaces" and "show profiles" work without it.
- netsh wlan set randomization and set profileparameter worked without administrator rights here.
- Saved profiles show as "All User Profile" or "Current User Profile"; match on "user profile".

Adapters and IP
- GetAdaptersAddresses (ctypes, in _net.py) is what ipconfig uses, and takes about 10 ms.
- Real adapters are told apart from virtual ones by PnPInstanceId (PCI\, USB\, SD\) under the
  network class key. Bluetooth PAN, Hyper-V, VirtualBox and Wi-Fi Direct adapters are virtual.
- IPv6 SuffixOrigin 5 (random) is what ipconfig calls a "Temporary IPv6 Address".
- DHCP lease times, the DHCP server and manually set DNS servers (NameServer) are in
  HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces\{GUID}, readable without admin.
- Metered Ethernet is HKLM\SOFTWARE\Microsoft\DusmSvc\Profiles\{adapter GUID}\*\UserCost (2 = metered,
  0 = not), applied by restarting DusmSvc. Not yet verified with a live toggle.

COM and WMI (comtypes)
- WMI rows from comtypes need row.Properties_("Name").Value, not row.Name.
- Network features (bindings) are MSFT_NetAdapterBindingSettingData in root\StandardCimv2, changed
  with row.ExecMethod_("Enable" | "Disable").
- HNetCfg.HNetShare (connection sharing) refuses even to list connections without admin. Read the
  sharing state from root\Microsoft\HomeNet (HNet_ConnectionProperties) instead.
- netcfg -s n lists installed network components without admin; installing (-c p|s|c -i id) and
  uninstalling (-u id) need it.

WinRT (pywinrt)
- Install each namespace as its own package (winrt-Windows.Networking.NetworkOperators and so on).
  Objects from a namespace whose package is missing can't be read.
- Await async calls with asyncio.run. Enums are Python enums (.name, Enum["NAME"]).
- The mobile hotspot API (NetworkOperatorTetheringManager) needs no admin. Windows has no API for the
  hotspot's "Share over" (Wi-Fi or Bluetooth), and it does not report the hotspot's live channel.

Registry and policy
- HKLM\SOFTWARE\Microsoft\Enrollments always has "Local Authority", "Cloud Authority" and "Deploy
  Authority" entries. They are Windows' own, not device management. Only other providers mean an
  organisation manages the PC.
- Reading HKLM\...\NetworkList\Profiles needs admin.
- Group Policy and device management can set a policy back at the next refresh, so say so whenever
  a page changes a policy value.

Services (sc)
- "sc query type= service state= all" lists every service, with SERVICE_NAME, DISPLAY_NAME and STATE.
  Slashes and "=" can be mangled by Git Bash, so call sc from PowerShell or Python.
- A service's startup type is the Start value under HKLM\SYSTEM\CurrentControlSet\Services\{name}:
  2 auto, 3 manual, 4 disabled (DelayedAutostart = 1 means auto, delayed). Readable without admin.
- sc config needs "start=" and its value as separate arguments: auto, demand (manual), disabled.

Devices (cfgmgr32, Plug and Play)
- Read devices through cfgmgr32 with ctypes: CM_Get_Device_ID_List_SizeW and CM_Get_Device_ID_ListW
  list them, CM_Locate_DevNodeW opens one, CM_Get_DevNode_Registry_PropertyW reads its names. Use
  flags 0 for every device and 0x100 (CM_GETIDLIST_FILTER_PRESENT) for the connected ones. 0x80 is
  a different flag and returns invalid parameter.
- A device that is not connected cannot be located, so read it from HKLM\SYSTEM\CurrentControlSet\Enum\{instance id}
  instead. The names there are the same, and it needs no administrator rights.
- Get-PnpDevice returns connected and not-connected devices together, and its Present property tells them
  apart. "-PresentOnly:$false" returns only the not-connected ones. Win32_PnPEntity lists only connected devices.
- Reading the parent through Get-PnpDeviceProperty takes about 60 seconds for 250 devices, one call each.
  CM_Get_Parent does it in milliseconds, so the tree uses the API.
- Names can be "@file.inf,%key%;Plain text". The plain text is after the ';'.
- Manufacturers are full names, such as "Advanced Micro Devices", not "AMD".
- Problem codes are the CM_PROB_* numbers. 22 is disabled, 28 is no driver, 45 is not connected. This PC
  had no problem devices, so only the codes for working and not-connected devices have been seen.

Event logs (Get-WinEvent, through PowerShell)
- events.py sends one PowerShell script per query, encoded with -EncodedCommand and given its request in
  the EVT_REQUEST environment variable, so no quoting can break it. The script returns JSON.
- Filter in the query (XPath) where you can: time, level, event id, record number, process id. Windows'
  XPath subset has no contains(), so "part of a provider's name" is matched in Python, after reading
  the whole time window. Keep the window short when you filter by provider.
- XPath times are UTC in the form 2026-10-15T12:00:00.000Z. Events come back in UTC and are shown local.
- Get-WinEvent messages cost about 3 ms each, so only ask for them where the text is shown (search,
  errors, shutdowns, inspect). Counting and grouping read without them.
- Crash data (event 1000) has named fields: AppName, AppVersion, ModuleName, ExceptionCode.
- Service events name their fields param1, param2 and so on. The service name is param1, except
  timeouts (7009, 7011), where param1 is the number of milliseconds and param2 is the name.
- Shutdown evidence: a clean shutdown is 6006, the next boot is 6005, an unexpected one is 6008, a
  restart without a clean shutdown is Kernel-Power 41, a requested one is User32 1074, a blue screen is
  BugCheck 1001 (the code is in its message).
- Application Hang (1002) is a different provider from Winlogon's 1002 on this PC. The crashes page
  matches the provider too.
- The Security log, and Microsoft-Windows-Diagnostics-Performance/Operational (boot time), return
  "Attempted to perform an unauthorized operation" to a terminal that is not elevated. The page turns
  that into the admin hint. Security also needs auditing on, and this PC's showed no 4625 events.
- wevtutil epl and cl need the administrator rights the log needs. --backup runs before clearing, and
  the clear is not run if the backup fails.
- The baseline file lives in %LOCALAPPDATA%\w11-cli-console, not in the project folder.

Windows lessons from the pages written without Windows (from documentation and community sources; none confirmed on a PC yet,
so each is also in OPEN ISSUES under "check")

Devices and drivers (device.py)
- pnputil exit codes: 0 success; 3010 worked, a restart finishes it; 1641 restart started; 259 no matching device or already a better
  driver. /export-driver <oem#.inf | *> <folder> exports third-party packages only (Windows 10 1607 and later).
- pnputil prints a banner first, so the page drops it from error text. /enum-drivers labels change with the language, so blocks are
  read by position and the published name by its shape (oem<number>.inf).
- _net.run_tool only says whether the exit code was 0. device.py reads the real code by watching subprocess.run (_exit_codes).

Network bytes (netmon.py, net bytes)
- Provider Microsoft-Windows-Kernel-Network {7dd42a49-5329-4832-8dfd-43d979153a88}. Data events 10/11 (TCP send/receive IPv4) and 42/43
  (UDP) confirmed; 26/27 and 58/59 (IPv6) from memory, so the page checks every id against Get-WinEvent -ListProvider.
- logman start/stop with -ets; Get-WinEvent -Path needs -Oldest for .etl files. The data events carry PID, size, daddr, saddr, dport, sport.

Defender (defender.py)
- Start-MpScan -ScanType takes QuickScan, FullScan or CustomScan. Remove-MpThreat takes no threat id (it removes every active threat).
- Tamper Protection locks real-time, behaviour, cloud, download and signature settings, including from PowerShell, and a Set-MpPreference
  can "succeed" without changing anything: always read back. MpCmdRun has -Scan -Cancel.
- Memory integrity is HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity\Enabled (read only here).
- Defender events: 5001 real-time protection off. Start-MpWDOScan needs a local administrator, Defender as the active antivirus and WinRE on,
  and restarts at once.

Privacy (privacy.py)
- ConsentStore (HKCU and HKLM) holds Value Allow/Deny per permission; the desktop-apps switch is NonPackaged\Value. Policy lives at
  HKLM\SOFTWARE\Policies\Microsoft\Windows\AppPrivacy (LetAppsAccess<Name> 0 user, 1 force allow, 2 force deny, plus _ForceAllowTheseApps,
  _ForceDenyTheseApps, _UserInControlOfTheseApps); precedence deny, allow, user. LastUsedTimeStop == 0 is read as "in use now".
- Per-user values: AdvertisingInfo\Enabled, Privacy\TailoredExperiencesWithDiagnosticDataEnabled, International\User Profile\HttpAcceptLanguageOptOut
  (1 = opt out), Explorer\Advanced\Start_TrackProgs. Policies: AllowTelemetry (1 = required only), the three System activity-history values.

Display (display.py)
- A process that is not DPI aware is told 96 DPI; the page asks for per-monitor awareness when a command runs, never at import.
- ChangeDisplaySettingsEx: flag 0 changes the mode for this session only, CDS_UPDATEREGISTRY saves it, CDS_NORESET is only valid with it. For
  several displays call once per display with UPDATEREGISTRY|NORESET, then once with a NULL device and mode to apply. The main display must be at
  0,0 and displays must touch edge to edge. DEVMODEW is 220 bytes (c_int32 and c_uint16, not c_long and c_wchar).
- SDC flags: INTERNAL 0x1, CLONE 0x2, EXTEND 0x4, EXTERNAL 0x8, APPLY 0x80. HDR: DisplayConfig info types 9, 10, 11; Windows 11 22H2 added 15, 16, 17.
- Scale and Night light have no documented setter; their state lives in undocumented values (Night light is a CloudStore blob): do not read or write them.

Bluetooth (bluetooth.py)
- Association endpoint protocol ids: classic {e0cbf06c-cd8b-4647-bb8a-263b43f0f974}, LE {bb7bb05e-5972-42b5-94fc-76eaa7084d49}. Watchers filter
  (System.Devices.Aep.ProtocolId:="{guid}") with DeviceInformationKind.AssociationEndpoint. Pairing uses customPairing.PairAsync(ceremonies, level);
  the PairingRequested handler runs on another thread, so take a deferral and resolve it from the main thread.
- Radio.GetRadiosAsync only sees radios of the same architecture (32-bit Python on 64-bit Windows finds none). Radio.SetStateAsync can raise
  ERROR_BUSY (retry); call Radio.RequestAccessAsync first. BluetoothMinorClass members share numbers, so decode the raw class of device.
- bthserv starts on demand, so "stopped" is normal. Windows has no documented way to connect or disconnect a paired device.

Sound (sound.py)
- IPolicyConfig (CLSID {870AF99C-171D-4F9E-AF0D-E63DF40C2BC9}, IID {F8679F50-850A-41CF-9C72-430F290290C8}) is undocumented; its method order after IUnknown
  is GetMixFormat, GetDeviceFormat, ResetDeviceFormat, SetDeviceFormat, GetProcessingPeriod, SetProcessingPeriod, GetShareMode, SetShareMode,
  GetPropertyValue, SetPropertyValue, SetDefaultEndpoint (slot 13), SetEndpointVisibility. Roles: 0 console, 1 multimedia, 2 communications.
- EnumAudioEndpoints with state mask 1|2|8 matches the Sound settings. "No default device" is HRESULT 0x80070490, not an error.
- Mono audio is HKCU\Software\Microsoft\Multimedia\Audio\AccessibilityMonoMixState (community only, so read only). The startup-sound policy is
  HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\DisableStartupSound. Classic dialog tabs: control.exe mmsys.cpl,,0 to ,,3.

Environment variables (environment.py)
- Variables live in HKCU\Environment and HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment. A value with %VAR% must be
  REG_EXPAND_SZ or it is not expanded. A new process gets system then user variables (user wins, only PATH is concatenated). Programs learn of a
  change from a WM_SETTINGCHANGE "Environment" broadcast; open terminals never see it. setx truncates at 1,024 characters, so it is not used.

Windows Update (update.py)
- WUA search criteria: IsInstalled, IsHidden, BrowseOnly (1 = optional), Type='Driver'|'Software', UpdateID. OperationResultCode 0 to 5.
  IUpdate.IsHidden is settable only by administrators. Install fails with E_ACCESSDENIED from a remote session.
- Pause by policy: PauseFeatureUpdatesStartTime / PauseQualityUpdatesStartTime (yyyy-MM-dd) under HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate;
  Windows adds 35 days. ExcludeWUDriversInQualityUpdate = 1 leaves drivers out. Windows 11 still writes "Windows 10 Pro" in ProductName: build 22000
  and up is Windows 11. A stopped wuauserv, BITS or UsoSvc is normal (on demand). wusa /uninstall /quiet is reported as deprecated on newer builds.

======================================================================
WHAT EACH SETTING IS FOR
======================================================================

These describe what the user wants from each page. Each intro should lead with the thing that
setting is most often used for. New pages follow the same order: the most common action first, the
risky one last with its warning, and a TIP that heads off the first thing that goes wrong.

firewall (fw): Windows Firewall. fw shows each profile and the networks this PC is on, fw rules lists the rules with filters, and fw rule <id> explains one. Turning a profile off asks first and warns about public networks, and turning off a profile also stops the net block rules. Rules are changed on and off, not deleted.

netmon (net, nm, traffic): What is on the network right now, and what is responsible for it. The overview answers "is anything unusual?" in one screen (typing net alone runs it); "net live" keeps it updating; "net <id>" explains one connection and offers the two actions that change something (kill the program, block the address), each asking first. Shows connections, programs, domains and bytes per adapter. Bytes per program are the opt-in "net bytes", which runs a Windows trace session for a few seconds as administrator, always stops it, and keeps the result for an hour so the lists can show it.

settings (menu): The front door. Someone who does not know the commands types "settings" and sees every setting in one numbered, blue list, with what each does and the first command to type. They can then type a number or a name at the prompt to open a setting's intro. It should always be the easiest thing to find, so every new page has to show up here with a clear SUMMARY.

volume (vm, vol): Quick control of how loud each app is, when several are playing (a browser, Discord, a game). The intro leads with vm ls, then vm <id> <0-100>. Say that ids are numbered by name, so they shift.

brightness (bn, b, screen, ...): One number, most of the time. Most people type bn 40, so the intro leads with the number form, then get, up and down. info is last, because it is for troubleshooting. The TIP names DDC/CI, since that is the usual reason it fails on an external monitor.

startup (su, start): Speed up sign-in by stopping apps from starting, safely. The intro stresses that on and off are reversible and that rm is the one that deletes. Say when changes apply (next sign-in) and that all-users apps need an administrator terminal.

apps (app): Find an installed app and uninstall it, with the same list you would see in Settings. Lead with apps ls. Uninstalling always asks first, and the intro says it can't be undone.

process (prc): Find what is using the CPU or memory and end it. The intro leads with prc ls, then prc ls /verbose for live numbers, then prc kill last, with the warning that unsaved work is lost. Red rows are Windows system programs, and the TIP says so.

wifi (internet, wf): Getting online quickly, then everything Settings has for Wi-Fi. The most common path is wifi on, which joins the best saved network. For a new network it is wifi ls, then wifi <id> on, which asks for the password. wifi info is the readable ipconfig: the radio (band, channel, signal, speed), then the addresses, then the settings, each section in its own colour. Known networks (wifi known) are every saved profile, in range or not, with forget, auto-connect, metered and random-address switches each. The settings group covers ip, dns, metered, random hardware addresses, 802.1X (wifi auth, which explains that it only applies to work and school networks), sharing and features, then the hotspot. The intro leads with the everyday actions and puts the settings under headings. The TIP says to run wifi ls first, and it should mention that Windows needs Location on to show network names.

ethernet (eth, lan, wired): The wired connection, the same as Settings > Ethernet and the adapter's Properties. It leads with eth info, which flags a self-assigned 169.254 address as "no DHCP server answered", the usual reason a cable "has no internet". Then ip, dns, metered (written where Settings keeps it, under DusmSvc, and the Data Usage service is restarted so it applies), 802.1X (eth auth: on starts Wired AutoConfig and sets it to start with Windows; method, who signs in, remember credentials, fallback and single sign-on), sharing and features. If a PC has more than one wired adapter, eth ls numbers them and eth <id> <command> picks one.

hotspot (hs, mobilehotspot): Share this PC's internet, the same as Settings > Mobile hotspot. hs on turns it on and shows what another device needs: the name, password, band and security. Name, password (typed hidden, twice), band and security can be changed in one command each, and the page says that changes made while it is on apply at the next start. hs from lists the connections that can be shared, and hs on <id> shares one. 'Share over' (Wi-Fi or Bluetooth) has no API, so hs over opens the Settings page at that choice and says so. wifi hotspot ... goes to the same page.

location (lc): The place to see and change everything about location. Typing lc on its own lists every location setting with what it is set to now, and a plain-words explanation of each one. lc why says why location is off or blocked and what would fix it, and with --json it is the first thing an agent should run for a location problem. Location services is the master switch for the whole PC; lc off sets the same Windows policy as gpedit's "Turn off location", and lc on puts it back. If an organisation's policy is what turned it off, lc on refuses and explains, and only lc on --override-management (after the owner agrees) overrides it. Access for apps and the per-app switches come next, then the 7-day list of apps that used location, then the override. The intro should say that the admin-only switch is the one that needs an administrator terminal.

regedit: An interactive Registry Editor, for people who want to look inside Windows and not just flip switches. Typing regedit opens its own prompt, with the path shown in it, and the editor keeps control until the user types exit or 0. It lists the root hives as numbers, and a number opens an item. Its commands are the usual ones: ls, cd, get, add, set, rm, mkdir, rmdir. Destructive steps ask first, and deleting a key with anything under it means typing its name. It never deletes a hive or one of its top two levels, and it never gets around Windows' permissions.

services (svc): The Windows services list, the same as services.msc. It leads with svc ls, then svc <id> to see one, then on, off and restart. Ids are numbered by name, so they shift, and a name works too. Listing and showing need no administrator rights. Every change does, and the admin check runs before anything is announced. Stopping and disabled ask first. The intro says that disabled survives a restart and that setting auto or manual undoes it.

events (evt): The Windows event logs, read so that an agent can reconstruct what happened before a problem. Everyday commands are evt errors, evt recent and evt search. Then the problems by cause (crashes, shutdowns, boot, drivers, services, network, security), then patterns over time (correlate, timeline, frequency, baseline), then logs (list, filter, export, watch, clear). Times read as 2h or 3d. Most logs need no administrator rights; the Security log and boot times do, and the page says so. evt clear is the only change, and it asks for the log's name to be typed, with a backup first unless --no-backup is given. --yes does not skip it.

device (dvc): The Device Manager list, and changes to it. It leads with dvc ls, then dvc <id> for one device (its driver, what it is plugged into, and its status), then dvc errors for what is wrong. Ids are numbered by name, so they shift. The TIP says that reading needs no administrator rights. The changes (enable, disable, restart, driver add and rm) need an administrator terminal, check it before asking, and read the device back. The 'not connected' state is not an error, and the errors page says so. The changes (enable, disable, restart, rescan, rollback, driver add and rm, drivers export) need an administrator terminal, check it before asking, and read the device back. rescan is harmless and does not ask. A change that exits 3010 worked and needs a restart: the page says so. backup saves a JSON inventory under device-snapshots; diff answers 'what changed since it last worked'.

defender (def, av, wd): Windows Security's virus and threat protection. def gives a verdict, then each protection, signatures, scans, threats and services. def why lists what is wrong with the command that fixes each. Scans run in the background. Turning protection off asks and states the cost. Tamper Protection and organisation policy are reported, never bypassed. Exclusions and def clean ask first.

privacy (priv, perm, permissions): who can use the camera, microphone, location and the rest, and what is using them right now. priv answers it in one screen; priv now answers "is anything using my camera this second". Switches go from priv camera off to one app with priv camera 3 off, and priv why finds the first switch that blocks. Turning a permission on asks first. A policy-owned switch is refused, never overridden. priv general covers the privacy settings with a documented value or policy. Location is only read here: lc changes it.

display (dsp, res, resolution): Settings > System > Display. dsp lists each display and says in plain words what could be better (a 144 Hz monitor at 60 Hz, a non-native resolution, a scale different from the recommended one), each with its fix command. Everyday: res and hz; then rotate, primary, placement, pos, hdr, project. Every picture change is tested, applied unsaved and reverted after 15 s unless y is pressed. Scale and Night light open Settings. No administrator rights.

bluetooth (bt): See and manage Bluetooth. bt shows the radio and the paired devices. bt on|off switches the radio, and asks first if devices are connected, because a Bluetooth keyboard would stop. bt scan then bt pair <n> pairs a device in pairing mode, with Windows' own questions answered here: a code match is never answered by --yes, and an agent passes --code instead. bt rm unpairs and asks first. bt why lists what stops Bluetooth working. Connecting and disconnecting a paired device has no Windows API, so bt connect opens Settings.

sound (snd, audio): Which speakers and microphone Windows uses, and "why is there no sound". snd lists the devices (playback, then recording) with the defaults marked; snd default <id> switches and reads back. Device volume and mute are per device (one app's volume is vm). snd why walks the usual causes and names the fix for each. Anything Windows gives no way to do (Mono audio, per-app output, turning a device on or off) opens the right Settings page. Only the startup-sound policy needs administrator rights.

environment (env, vars): Environment variables and PATH, like Advanced system settings but with a diff and an undo. The common jobs are env path add, env set and env path clean. Yours is the default; --system needs administrator, checked first. Every change saves a JSON backup, and protected names need their name typed.

update (wu, winupdate, updates): Windows Update. wu shows how updates are doing and why they may not arrive: a verdict first (healthy, or what needs attention with the command that fixes it), then the Windows version, last check, restart waiting, pause, policy from an organisation, and the services. wu ls searches and numbers the pending updates; wu install <id>|all downloads and installs them (administrator, asks, never restarts). Every action re-searches and matches by the update's own id, because ids shift. wu history and wu failed explain results in plain words; wu why runs every check. Pausing is the documented Windows Update for Business policy, so Settings may say "managed by your organization"; Windows Home ignores it and gets the Settings page instead. Anything Windows has no documented way to change (active hours, metered downloads, restart notices) is read here and changed in Settings (wu open).
